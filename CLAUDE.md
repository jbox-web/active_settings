## Overview

`active_settings` is a Ruby gem for managing application settings (typically in Rails), heavily inspired by the [config](https://github.com/rubyconfig/config) gem. Its distinguishing design choice: it does **not** define a global `Settings` constant for you. The user subclasses `ActiveSettings::Base`, so they own the class and can add their own methods to it.

## Commands

- Run the full test suite: `bin/rspec`
- Run a single spec file: `bin/rspec spec/active_settings/base_spec.rb`
- Run a single example by line: `bin/rspec spec/active_settings/base_spec.rb:50`
- Lint: `bin/rubocop` (config in `.rubocop.yml`)
- Default rake task (runs specs): `bin/rake`
- `bin/guard` watches files and re-runs specs (see `Guardfile`).

CI (`.github/workflows/ci.yml`) runs Rubocop on Ruby 3.2 and RSpec across Ruby 3.2–4.0 + truffleruby. Minimum supported Ruby is 3.2.0. Coverage is generated by SimpleCov into `coverage/` (HTML + JSON) on every `bin/rspec` run.

## Architecture

The gem is loaded via Zeitwerk (`Zeitwerk::Loader.for_gem` in `lib/active_settings.rb`), so file paths must match constant names.

Three layers:

1. **`ActiveSettings` module** (`lib/active_settings.rb`) — module-level configuration via `mattr_accessor` (e.g. `fail_on_missing`, `use_env`, `env_prefix`, deep-merge options) plus the pure functions that do the heavy lifting: `from_hash` (recursively wraps Hashes into `Config` objects, including inside Arrays), `to_hash` (evaluates stored Procs) / `to_raw_hash` (leaves Procs untouched — used by `merge!`), `from_env` (builds a nested hash from `ENV`, respecting `env_prefix`/`env_separator` and casting values as strict base-10; raises `EnvKeyConflictError` on scalar/nested key clashes), `deep_merge_hash!`, `deep_freeze` (freezes nested `Config`s **and** arrays), and `load_yaml_file` (ERB-evaluated YAML with alias support; returns `{}` for an empty file, raises `InvalidSettingsFileError` for a non-mapping).

2. **`ActiveSettings::Config`** (`lib/active_settings/config.rb`) — subclass of `OpenStruct` providing the runtime access API: method chaining, `[]`, `fetch` (with default value or block), `dig`, `key?`, `to_hash`/`to_h`, `to_json`, `merge!`, and recursive `freeze`. `key?`/`fetch` test key *existence* (via `marshal_dump`), so a key whose value is `false`/`nil` is still found. When `ActiveSettings.fail_on_missing` is true, `method_missing` raises `KeyError` on unknown keys (but never for setters).

3. **`ActiveSettings::Base`** (`lib/active_settings/base.rb`) — `Singleton` subclass of `Config` that users inherit from. Its `initialize` delegates file loading to the private `load_config` (see order below), then wraps the result via `from_hash`, merges `ENV`, and freezes nothing by default.

### Settings loading order (in `Base#load_config`)

Configuration is deep-merged in this precedence (later overrides earlier):

1. The `source` YAML file (e.g. `settings.yml`) — required, else `SourceFileNotDefinedError`.
2. Environment file `settings.<environment>.yml` (same dir), if `environment` is set.
3. Platform default `settings_files/<platform>/default.yml`, if `platform` is set.
4. Platform+environment `settings_files/<platform>/<environment>.yml`, if both set.

Back in `initialize`, once `load_config` returns: `before_initialize!` hook runs, then `ENV` vars are merged (via `from_env`), then the optional init block, then `after_initialize!`.

Subclasses declare `source`, `environment`, and `platform` as class-level DSL methods (memoized). Override the hook methods (`before_initialize!`, `after_initialize!`, `on_settings_file_load(file, loaded:)`) in your subclass for custom behavior. The DSL keyword was historically `namespace`, renamed to `environment`; `platform` was added later.

### Validation

Optional, backed by `dry-schema`. `ActiveSettings::Validation::Schema#schema(&block)` (extended onto the class) defines a Dry schema; `Validate#validate!` (included) runs it against `to_hash` and raises `ActiveSettings::Validation::Error` with a formatted message keyed by `env_prefix`. `validate!` is a no-op if no schema is defined and must be called explicitly.

### Errors

`ActiveSettings::Error::{BaseError, SourceFileNotDefinedError, EnvPrefixNotDefinedError, InvalidSettingsFileError, EnvKeyConflictError}` and `ActiveSettings::Validation::Error`.

## Tests

RSpec with `disable_monkey_patching!`, random order, and `raise_errors_for_deprecations!`. Specs build anonymous subclasses (`Class.new(ActiveSettings::Base)`) and use the `get_fixture_path` helper (defined in `spec_helper.rb`) to point `source` at files under `spec/fixtures/`.
